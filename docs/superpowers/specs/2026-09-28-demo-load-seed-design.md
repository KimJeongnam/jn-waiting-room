# 데모 부하 시드 및 빠른 Polling 설계

## 목표

- 빈 활성 슬롯에 들어갈 수 있는 대기 요청은 1초 안에 입장 상태를 다시 확인한다.
- 데모 실행에서 활성 테스트 사용자 1,000명과 대기 테스트 사용자 10,000명을 초기 구성한다.
- 1~5분 랜덤 만료는 최초 활성 테스트 사용자에게만 적용한다.

## 설계

Redis Polling Lua는 대기 순번과 활성 슬롯 수를 함께 읽는다. 현재 순번이 빈 슬롯 수 이내이면 빠른 Polling 대상으로 반환하고, 서비스 계층은 해당 요청에만 1초 주기를 적용한다. 그 외 요청은 기존 장기 Polling 주기를 유지한다.

데모 시드는 `demo` Spring 프로필과 명시적인 활성화 속성이 모두 설정된 경우에만 실행한다. 기존 `register`, `admitNext`, `enter` 상태 전이를 재사용해 활성 테스트 사용자 1,000명을 `ENTERED`로 만들고 각 슬롯에 현재 시각부터 1~5분 사이의 랜덤 만료시간을 지정한다. 이후 대기 테스트 사용자 10,000명은 `WAITING`으로 등록한다.

실제 브라우저 요청과 시드 이후 입장자는 기존 `admissionTimeout` 및 `maxSessionDuration`을 그대로 사용한다. 랜덤 만료시간은 데모 시드의 최초 활성 사용자에게만 전달한다.

## 재실행 및 격리

데모를 다시 시작하면 고정된 데모 테스트 ID 범위만 기존 상태 Key와 ZSET에서 제거하고 동일한 초기 상태를 다시 생성한다. 실제 브라우저 요청과 운영 데이터는 제거하지 않는다. 운영 프로필에서는 시드 컴포넌트가 생성되지 않으며 데모 설정의 기본값은 비활성이다.

## 검증

- 여유 슬롯 범위의 요청만 1초 Polling 대상인지 Redis 통합 테스트로 검증한다.
- 데모 시드가 정확히 활성 1,000명, 대기 10,000명을 생성하는지 검증한다.
- 테스트 활성 슬롯 만료가 1~5분 범위인지 검증한다.
- 일반 요청의 기존 만료 설정이 변경되지 않았는지 전체 테스트로 확인한다.
